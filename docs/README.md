## The 60-second version

**We are building** a 3B-activated-parameter coding model, `MenteE Code 3B`, served over an
OpenAI-compatible API for OpenCode-class agents. It is a QLoRA fine-tune of
`Qwen/Qwen3-Coder-30B-A3B-Instruct` (Apache-2.0) ✅, trained on trajectories generated by
`Qwen/Qwen3-Coder-Next` (Apache-2.0) ✅ — self-hosted, so there is no teacher-API bill and
no teacher-licence ambiguity.

**The thesis** (`01`) is that a 3B-activated MoE *can* behave like a 300B model on agentic
coding — and that five mechanisms make it happen. Three we inherit from the base model.
Two, **execution-verified post-training** and **long-horizon recovery**, only our data can
supply. 🎯 That is the whole project.

**The two layers** (`01` §2.5) — the one that is most often confused:

| Layer | Baked into the weights? |
|---|---|
| **① Wire format** (how a tool call is serialised) | **Yes** — it is the base model's native format, reused byte-for-byte |
| **② Tool schema** (which tools exist, their parameters) | **No** — it is a request parameter, supplied by whatever agent is driving |

So the model is **not** trained to one harness's tool names. It is trained to read the
schema it is given. OpenCode is one adapter among several, not a dependency.

**So: is more data + better data enough?** Mostly — but not alone:

```
release quality ≈ base_model × data_quality × verification × format_conformance × eval_discipline
```

Multiplicative. Any factor near zero makes the product near zero, and **no amount of extra
data compensates.** More data buys two of the five factors. The other three are decisions
(made here) and discipline (implemented in `06`–`07`).

**The cost** is ~$30 to prove the idea and ~$1,020 to ship v0.1 with a 10-day public beta.
At **~$0.02 per successful task** versus ~$2.70 for a frontier API. 📐

**The risk** is that a fine-tune fails to beat its own free base model. The kill switch is
written down on day 0 (`00` §3.1) precisely so that on the day it happens, the decision has
already been made.

## Conventions used in these docs

| Marker | Meaning |
|---|---|
| ✅ | **Verified** against a primary source, with a link and an access date |
| 📐 | **Assumption** — needs a measurement. Each one has a resolution step in `12` |
| 🎯 | **Recommendation** — our call, with the reasoning shown |
| 🔴 / 🟡 / 🟢 | Risk severity: high / medium / low |

**Facts, assumptions and recommendations are never mixed in the same sentence without a
marker.** Where a number is 📐, it does not go in the model card until it has been measured.
